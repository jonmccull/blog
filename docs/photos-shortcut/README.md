# Add to Photos: the iOS shortcut

Adds photos to the Photos page from a phone. Share one or more pictures from the Photos app to
**Add to Photos** (or run it and pick them), answer one question (where they were taken, or leave
it empty) and a pull request appears a couple of minutes later with each photo resized, its camera,
exposure and date read from the EXIF, and the location filled in. Only the `alt` text is left to
write on the pull request.

The originals never enter git history. The shortcut uploads them as assets on a **draft release**
(GitHub hosts those outside the repository and a draft makes no tag), then sends a
`repository_dispatch` event named `photos` with the release id. The `photos` workflow
(`.github/workflows/photos.yml`) fetches the assets into `photos/inbox/`, runs the same ingest as
the folder route, opens the pull request and deletes the release. If no pull request opens, the
release is kept so nothing is lost; the run summary names it.

## One-time setup

1. **A token.** On github.com: Settings → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token. Resource owner `jonmccull`, repository access: only
   `jonmccull/blog`, permissions: **Contents: Read and write** (Metadata comes with it). Expiry is
   your call; a year is fine. Copy it.
2. **The shortcut.** Open [`Add to Photos.shortcut`](Add%20to%20Photos.shortcut) on the phone (from
   github.com it downloads; open it from Files, or AirDrop it from a Mac). Shortcuts asks to add it;
   it is signed for anyone.
3. **Paste the token** into the first Text action, replacing `PASTE-GITHUB-TOKEN-HERE`. Nothing
   else needs changing.
4. **Show in Share Sheet** is on already; the shortcut accepts images.

The workflow needs "Allow GitHub Actions to create and approve pull requests" switched on under
Settings → Actions → General, as for the folder route. Without it the run fails at the pull
request step and keeps the release.

## First run: check the caption

Share one camera JPEG. When the pull request opens, the body should show the camera, lens,
exposure and date under the picture. If it says "no EXIF found", the metadata did not survive the
phone: open the shortcut and check that **Convert Image** has _Preserve Metadata_ on. Sharing from
the Photos app passes the full file; some other apps hand over a stripped copy.

## What the shortcut does, action by action

The file is generated by [`make-shortcut.py`](make-shortcut.py) (`python3 make-shortcut.py
out.shortcut`, then `shortcuts sign --mode anyone --input out.shortcut --output "Add to
Photos.shortcut"` on a Mac). Rebuilding it from the script is the way to change it; this list is
for reading it in the Shortcuts app.

1. Comment, then **Text** holding the token → variable `Token`.
2. **Ask for Input**: "Where were these taken?" → variable `Location` (may be empty).
3. **Count** the shared photos, for the notification.
4. **Current Date**, formatted `yyyyMMdd-HHmmss`, to name the release.
5. **Get Contents of URL** `POST https://api.github.com/repos/jonmccull/blog/releases` with
   `tag_name: photos-inbox-<date>`, `name`, `body`, `draft: true`. A draft makes no tag.
6. **Get Dictionary Value** `id` → variable `ReleaseID`.
7. **Repeat with Each** photo: **Convert Image** to JPEG at quality 0.9 with _Preserve Metadata_,
   then **Get Contents of URL**
   `POST https://uploads.github.com/repos/jonmccull/blog/releases/<id>/assets?name=photo-<date>-<n>.jpg`
   with the image as the request body (`Content-Type: image/jpeg`). The name is the batch's time
   and the photo's place in it, because a photo shared from the Photos app carries no file name
   (the first real run uploaded `default.jpg`); rename on the pull request if you want the camera's.
   HEIC photos become JPEG here; camera JPEGs are re-encoded once, then resized to 3000px by the
   workflow anyway.
8. **Get Contents of URL** `POST https://api.github.com/repos/jonmccull/blog/dispatches` with
   `event_type: photos` and `client_payload: { release_id, location }`.
9. **Show Notification**: "Sent N to jonm.cc. A pull request opens in a couple of minutes."

Every GitHub call carries `Authorization: Bearer <Token>`, `Accept: application/vnd.github+json`
and `X-GitHub-Api-Version: 2022-11-28`.

## When something goes wrong

- **The shortcut stops with an HTTP error** at step 5: the token is wrong, expired, or lacks
  Contents write. At step 7: the upload itself failed; try again on Wi-Fi.
- **No pull request after five minutes**: open Actions → photos. A run that failed at "Open a pull
  request" has kept the release (Releases → Drafts). Fix the cause, then run the workflow by hand:
  Actions → photos → Run workflow, with the `release_id` from the run summary and the location.
  Delete the draft release afterwards if you no longer want it.
- **To run the route without the phone**: create a draft release, upload a JPEG as an asset, and
  run the workflow with its id, from any branch. That is how it was tested.
